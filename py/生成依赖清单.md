在 Python 开发中，生成依赖清单（通常命名为 `requirements.txt`）主要有三种常用方法。你可以根据项目的复杂程度选择最适合的一种。

---

## 1. 使用 `pip freeze`（最简单，但不推荐用于复杂环境）

如果你在一个**虚拟环境**（venv 或 conda）中工作，并且环境里**只安装了**该项目需要的包，可以使用这个命令：

```bash
pip freeze > requirements.txt

```

> **注意：** 这个命令会记录当前环境下安装的**所有**包。如果你在全局环境（Global）下运行，它会把很多无关的库也写进去，导致文件臃肿。

---

## 2. 使用 `pipreqs`（最推荐，按需生成）

`pipreqs` 是一个非常智能的工具，它会扫描你的代码文件（`.py`），只把代码中 `import` 过的库写入 `requirements.txt`。

### 操作步骤：

1. **安装 pipreqs：**
```bash
pip install pipreqs

```


2. **在项目根目录下运行：**
```bash
pipreqs . --encoding=utf8 --force

```


* `.` 表示当前目录。
* `--encoding=utf8` 防止 Windows 下出现编码报错。
* `--force` 如果已存在该文件则覆盖。



---

## 3. 使用 `pigar`（更精确）

`pigar` 比 `pipreqs` 更强大的一点是，它能识别出某个包属于哪个具体的库（有时候 `import` 的名字和 `pip install` 的名字不同）。

### 操作步骤：

1. **安装：**
```bash
pip install pigar

```


2. **生成：**
```bash
pigar generate

```



---

## 总结与建议

| 工具 | 优点 | 缺点 |
| --- | --- | --- |
| **pip freeze** | 无需额外安装工具 | 会包含无关的依赖，环境污染严重 |
| **pipreqs** | **最常用**，仅根据代码生成 | 偶尔会漏掉动态加载的插件 |
| **pigar** | 极其精准，支持显示导入位置 | 运行速度稍慢 |
